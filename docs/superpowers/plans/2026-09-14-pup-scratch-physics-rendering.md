# Pup Scratch Physics + Rendering Plan

**Date:** 2026-09-14  
**Target:** Puppy Clicker / Puppy Casino / Pup Scratchers  
**Repository:** `markhitchk/pup-clinker`

## Goal

Make Pup Scratchers feel like a physical scratch card rather than a coarse touch mask. The visible Pup Coin must stay centered on the exact contact point used by the scratch engine, and fast/slow drags should change the scratch trail in a controlled, device-independent way.

## Root cause found

The scratch engine stores coin/scratch positions in card-local coordinates, but the visible `PupCoin` is a child of a `Box` whose `contentAlignment` is `Alignment.Center`. The coin then applies an offset as though its origin were top-left. That adds the Box center to the visual placement, so the rendered coin does not match the point being scratched.

The current scratch mask is also relatively coarse (32 x 14), uses per-pointer-event distance instead of time-normalized velocity, and marks only one circular sample per drag event. Fast drags can therefore produce blocky or discontinuous trails.

## Implementation

- [x] Anchor the scratch-card Box at `Alignment.TopStart` so coin coordinates and scratch coordinates use the same origin.
- [x] Clamp the coin center so the visible coin cannot move beyond the card bounds.
- [x] Increase scratch coverage resolution for cleaner edges.
- [x] Convert drag speed to pixels-per-millisecond using pointer timestamps.
- [x] Use speed-sensitive contact radius tied to the actual Pup Coin radius.
- [x] Interpolate scratch samples between the previous and current coin position to prevent gaps on fast swipes.
- [x] Keep weighted follow/drag behavior while ensuring the scratch path is generated from the same filtered coin position that is rendered.
- [x] Improve Pup Coin rendering with layered metal faces, rim detail, highlight, and physical-looking depth.
- [x] Update casino animation contract coverage for the new alignment and physics markers.

## Behavioral constraints

- Casino outcomes remain committed before scratching.
- UI physics never generates or changes the prize result.
- Existing Treat costs, RTP, save/recovery behavior, and settlement threshold remain unchanged.
- Scratching remains touch-driven and does not require new Android permissions.

## Acceptance checks

1. The center of the rendered Pup Coin overlays the center of the newly removed coating.
2. Dragging quickly does not leave large unscripted gaps in the trail.
3. Slow movement produces a narrower trail than fast movement.
4. The coin remains fully visible inside the scratch-card surface.
5. The card still auto-reveals only after the existing reveal threshold is reached.
6. Casino contract tests continue to assert that outcomes are not generated by UI animation/physics.
