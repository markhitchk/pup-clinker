# Puppy Clicker — Android

This is the existing native Android edition of Puppy Clicker, moved from the repository root without changing its game source or application identity. It uses Kotlin, Jetpack Compose, Java 17, and Android SDK 35.

## Open and build

Open this `App/` directory as the Gradle project in Android Studio. From a terminal at the repository root:

```bash
cd App
gradle :app:assembleDebug
gradle :app:bundleRelease
```

Gradle 8.9, Java 17, Android SDK 35, and Python 3 are required by the existing build configuration. Google Play production releases are Android App Bundles written to `App/app/build/outputs/bundle/release/`. GitHub Actions signs the AAB with the configured Google Play upload key, verifies its expected certificate fingerprint, and leaves final APK signing to Google Play. See [`SIGNING.md`](SIGNING.md).

## Existing project layout

- `app/` — Android application module, Kotlin source, resources, and existing packaged SVG artwork.
- `tools/` — SVG compiler, artwork checks, and original project utilities.
- `admin/` — Existing administration documentation.
- `build.gradle.kts`, `settings.gradle.kts`, and `gradle.properties` — Android project configuration.
- `SIGNING.md` — Google Play App Signing and upload-key documentation.

The application ID remains `com.harleytg.puppyclicker`. The current Gradle configuration determines the effective version, rather than historical README version notes. No game mechanics, character IDs, Android package names, or signing keys were changed during this folder organization.

## Shared artwork

A future asset synchronization step can use the shared folder without changing the current game.

They use paths relative to the old Android project root, so run them from `App/` only after reviewing their historical version assumptions. They are not part of the normal build.


## Google Play app updates

Google Play is the production delivery channel. The app may still read the repository's latest published GitHub Release for release notes and update metadata, but the user-facing update action always opens the Google Play listing; it does not install GitHub APK assets.

Keep the Android build number in the GitHub Release notes using one of these forms:

```text
Build: 27
```

or

```text
Version code: 27
```

The value must match `versionCode` in `app/build.gradle.kts`. The human-readable GitHub tag (for example `v1.8.0`) is used as the displayed version name; update eligibility is determined by the numeric build/version code. Drafts and prereleases are ignored by the latest-release update check.

For production, upload the signed `.aab` generated by `:app:bundleRelease` to Google Play. Do not publish a repository-signed APK as an update for Play-installed users.
